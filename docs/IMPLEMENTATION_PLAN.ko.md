이 문서는 [핵심 설계](DESIGN.ko.md)를 실제 결과물로 옮기는 순서와 각 단계의 완료 기준을 정한다. 기존 `DxPumpV0.76`은 수정·삭제하지 않는다.

## 단계 0 — 기술 스택과 개발 기반

**목적:** 실제 코드를 시작할 수 있는 도구·빌드·테스트 기반을 만든다.

**결정할 항목:** 렌더러, 오디오, BGA 영상, USB 입력, 빌드 시스템, 테스트 프레임워크.

확정한 스택은 Windows 전용 **C++20 + Direct3D 11 + FMOD + Media Foundation + Raw Input/DirectInput + CMake**다. 이 선택은 기존 C++/DirectX 경험을 현대적으로 이어가면서 USB 발판과 BGA를 직접 제어하기에 적합하다.

**완료 기준:** 빈 창을 열고 닫을 수 있으며, 개발/배포 빌드와 최소 자동 테스트가 모두 실행된다. **상태: 2026-08-27 완료.**

## 단계 1 — 런타임 골격과 데이터 경계

**목적:** 이후 기능이 섞이지 않도록 게임 루프·리소스·씬·채보 모델의 최소 경계를 구현한다.

- `GameApplication`, `SceneManager`, `ResourceCache`, 1280×720 논리 뷰포트
- `Chart`, `TimingMap`, `PlaySession`, `ResultData`의 불변 데이터 모델
- `MainMenu → SongSelect → Gameplay → Result` 빈 씬 전환
- 기본 테마 매니페스트와 리소스 키 조회

**완료 기준:** 더미 곡/더미 채보를 골라 각 씬을 전환해도 리소스 경로와 게임 상태가 씬 코드에 하드코딩되지 않는다.

**상태: 로컬 `NewSongToGod` 연동으로 Stage 02 / State 11까지 완료, 단계 2 완료 기준 통과.**

## 단계 2 — 첫 플레이 가능 수직 슬라이스

**목적:** 한 곡을 처음부터 끝까지 정확한 시간 기준으로 플레이한다.

- `AudioClock`과 음악 재생(현재 Debug 시계는 의도적인 임시 어댑터)
- 탭 노트 채보 로딩, 활성 노트 뷰, 스크롤 속도 조절(State 10에서 `NewSongToGod_10.stp`를 수정 없이 가져옴)
- 키보드 입력, 시간 오차 판정, 자동 Miss
- 콤보·점수·기본 게이지·결과 화면
- 정적 BGA 대체 배경
- 박→시간 변환과 판정 구간 자동 테스트

**완료 기준:** 스크롤 속도를 바꿔도 판정 시간창은 같으며, 한 곡의 결과가 정확히 집계된다.

**상태: 로컬 연동 빌드에서 완료.** 첫 플레이 가능 수직 슬라이스는 로컬 FMOD 곡 시계, 이관한 레거시 탭 채보, 시간 기반 판정, 점수/콤보/에너지, 정적 BGA와 안전한 대체 배경, Result 전달을 갖춘다. 롱노트 규칙, 판정 이펙트 애니메이션, 영상 BGA는 단계 3에서 구현한다.

## 단계 3 — Pump 스타일 게임플레이와 장면 연출

**목적:** 기본 플레이를 롱노트·게이지·UI 모션을 갖춘 리듬 게임으로 완성한다.

- 롱노트 헤드/틱/끝과 가변 `tickPolicy`
- 규칙셋 기반 게이지·게임오버·등급
- 판정, 콤보, 리셉터, 발판, 게이지의 이펙트 풀
- 1280×720 UI 레이아웃과 `SceneTimeline`
- 곡별 BGA 영상 재생, 영상 지연 시 프레임 건너뛰기, 정적 대체

**완료 기준:** 같은 길이의 롱노트에 서로 다른 콤보 수를 설정할 수 있고, BGA·노트·판정이 같은 음원 시간에 동기화된다.

## 단계 4 — 채보 제작 도구와 콘텐츠 이관

**목적:** 고정 16비트 표에 의존하지 않고 실제 곡을 제작·검증한다.

- 브라우저 기반 Chart Editor 프로젝트
- 임의 N 분할, 3연음, BPM/박자표, 탭, 드래그 롱노트
- 오디오 프리뷰/파형, 실행 취소, 복사/붙여넣기, 검증
- 원본 채보 저장과 실행용 컴파일 채보 생성
- 기존 `.stp` 탭 채보 가져오기

**완료 기준:** 편집기에서 만든 롱노트·3연음 채보가 컴파일되어 게임에서 같은 시점에 재생된다.

## 단계 5 — 스킨/테마 도구

**목적:** 코드 수정 없이 게임의 이미지를 교체하고 미리본다.

- `ThemeManifest` 검증·기본/사용자 테마 전환
- 이미지 슬롯 교체, 피벗/크롭/색상/투명도 조절
- 스프라이트 시트와 UI·이펙트 애니메이션 정의
- 씬별 미리보기, 테마 복제·가져오기·내보내기

**완료 기준:** 새 테마 패키지를 추가해 메뉴·게임·결과 이미지를 바꿔도 판정 위치와 게임 규칙이 변하지 않는다.

## 단계 6 — USB 발판과 2인 플레이

**목적:** 동일 모델 USB 발판 두 개를 안전하게 P1/P2에 배정해 동시 플레이한다.

- 컨트롤러별 독립 `PadDevice`
- 장치 배정·입력 검사·키 설정·입력 오프셋
- 재연결 처리와 키보드 대체 입력
- P1/P2 독립 판정·점수·게이지·결과 HUD
- Versus와 Co-op의 세션 규칙

**완료 기준:** 같은 모델 발판 두 개를 가운데 패널 입력으로 배정한 뒤, 두 사람이 독립 결과로 한 곡을 끝낼 수 있다.

## 단계 7 — 품질·배포 준비

**목적:** 포트폴리오와 실제 사용에 적합한 안정 버전을 만든다.

- 설정 저장, 전체 화면, 해상도/음량/모션 감소 옵션
- 로딩/오류/리소스 누락 처리
- 자동 테스트 확대와 장시간 플레이 점검
- 사용자 문서, 제작자 문서, 예제 테마/채보, 빌드 안내
- 플레이 영상과 개선 전후 포트폴리오 자료

**완료 기준:** 새 환경에서 문서만 따라 빌드·실행·테스트·곡 추가를 할 수 있다.

## 실행 원칙

1. 한 단계의 완료 기준을 확인한 뒤 다음 단계로 넘어간다.
2. 기능 요청이 생기면 가장 가까운 단계에 기록하고, 핵심 수직 슬라이스를 훼손하지 않도록 우선순위를 정한다.
3. 각 구현 변경은 관련 설계 문서·테스트·사용자 문서를 함께 갱신한다.
4. 큰 리소스/외부 라이브러리 도입, 기존 파일 이동·삭제, 배포는 사전에 범위를 확인한다.

## GitHub 마일스톤 운영

`PumpDX_Rebuild`는 레거시 폴더와 별도의 Git 저장소로 관리한다. 이 작업 공간에는 아직 Git 저장소나 연결된 원격 저장소가 없으므로, 단계 0에서 저장소를 초기화하고 사용자가 지정한 GitHub 원격 저장소를 연결한다. 원격 주소와 공개/비공개 여부는 연결 전에 확인한다.

- 작업 단위는 읽기 쉬운 작은 커밋으로 남기고, 커밋 메시지는 변경 목적을 설명한다.
- 각 단계의 완료 기준을 통과하면 `main`에 통합하고, 태그·GitHub Release를 만든다.
- 첫 권장 태그는 `v0.0.1-foundation`, 첫 플레이 가능 버전은 `v0.1.0-vertical-slice`다. 이후 주요 단계는 의미 있는 버전으로 올린다.
- 릴리스에는 변경 사항, 검증 방법, 알려진 제한, 실행 파일/영상 또는 스크린샷 링크를 기록한다.
- 소스·문서·테스트·작은 예제 채보/테마는 Git으로 관리한다.
- 빌드 산출물, IDE 캐시, 로그, 생성물은 `.gitignore`에 둔다. 대용량 음악/BGA는 저작권과 용량을 확인한 뒤 Git LFS 또는 별도 배포 방식을 선택한다.
- 레거시 `DxPumpV0.76`의 바이너리/중간 산출물은 새 저장소에 복제하지 않는다. 이관이 필요한 데이터와 권한이 명확한 리소스만 별도 커밋으로 가져온다.
